## 一、运行与验证

```bash
python3 -m unittest discover -s tests              # 全部测试
python3 -m unittest tests.test_machines -v         # 只看物理模型
python3 -m server.app --check                      # 服务自检
```

`tests/test_machines.py` 里的每条断言都对应一个"纸笔能算出来的答案"或一条独立公式。
如果改了模型导致测试失败，请先确认是模型错了还是测试过时了，并把结论写进提交说明。

## 二、单位与坐标约定（全局一致）

| 量 | 单位 | 说明 |
|---|---|---|
| 电压、电流 | V、A | SI |
| 转矩 | N·m | 负载为正表示阻力 |
| 机械角速度 | rad/s | 界面才换算成 rpm |
| 电角度 | rad | θ_e = p·θ_m，**p 是极对数** |
| 电感、磁链 | H、Wb | SI |
| 转动惯量 | kg·m² | 折算到电机轴 |
| 时间 | s | 子步默认 0.1 ms，控制周期默认 1 ms |

三条容易出错的约定，测试里都有断言：

1. **Clarke/Park 采用幅值不变约定**（系数 2/3）。αβ 矢量长度等于相电压幅值。
   另一种"功率不变"约定系数不同，两者不可混用（会差 1.5 倍）。
2. **积分与控制解耦**：`substep` 只影响数值精度，`control_period` 才决定控制行为。
   测试验证子步缩小 4 倍后结果变化小于 0.5%。
3. **负载是阻力型**：正值始终与当前转向相反。零速时按负载符号取方向，
   不会出现"负载把电机越推越快"。

## 三、各模型

### 直流机（`machines.DCMachine`）

```
L·di/dt = u − R·i − Ke·ω
J·dω/dt = Kt·i − b·ω − τL
```

状态 `(i, ω)`。`steady_state(u, τL)` 给出解析解，测试同时验证
"解析稳态是平衡点"与"动态积分收敛到解析解"。

### 三相异步机（`machines.InductionMachine`）

状态取**磁链**而不是电流：`(ψ_ds, ψ_qs, ψ_dr, ψ_qr, ω)`。
电压方程本来就是磁链导数，积分后再由 `i = L⁻¹·ψ` 读出电流——
这样代数误差不会被重新喂回积分，数值上远比"对电流积分"稳健。

```
dψ_ds/dt = u_ds − Rs·i_ds + p·ω_s·ψ_qs
dψ_qs/dt = u_qs − Rs·i_qs − p·ω_s·ψ_ds
dψ_dr/dt = −Rr·i_dr + p·(ω_s − ω)·ψ_qr
dψ_qr/dt = −Rr·i_qr − p·(ω_s − ω)·ψ_dr
Te = 1.5·p·Lm·(i_qs·i_dr − i_ds·i_qr)
```

`ω_s` 是**同步机械角速度** `2πf/p`，电角速度要乘 p。
漏掉极对数是异步机建模最常见的一处错误，测试用 `synchronous_speed()`
与转矩—转差曲线把它钉住。

另外提供：`torque_slip_curve()`（经典解析曲线，供独立对照）、
`max_torque_slip()`（最大转矩转差）。

### 永磁同步 / 无刷机（`machines.PMSMMachine`）

状态 `(i_d, i_q, ω, θ_m)`，转子 dq 坐标系：

```
u_d = R·i_d + Ld·di_d/dt − p·ω·Lq·i_q
u_q = R·i_q + Lq·di_q/dt + p·ω·(Ld·i_d + λm)
Te = 1.5·p·[λm·i_q + (Ld − Lq)·i_d·i_q]
```

### 逆变器（`inverter.py`）

不做开关级仿真。链路是：**参考电压 → 母线限幅 → 占空比**。

* 六个有效开关状态在 αβ 平面上的矢量长度是 `2·Vdc/3`；
* 线性区上界是内切圆 `Vdc/√3`（此时单个有效矢量占满整周期）；
* SVPWM 相对正弦 PWM 的电压优势是 `2/√3 ≈ 1.1547`，即 **+15.47%**。

占空比用零序（min-max）注入实现；矢量作用时间用**直接解 2×2 伏秒平衡方程组**得到，
不用三角恒等式——`tests` 里有一条测试用真实开关矢量重建参考矢量，
误差必须到机器精度。

> 实现提示：这条不变量是 SVPWM 实现里最容易写错的地方。
> 曾有版本因为系数差了 15.5%，占空比照样画得出来，但输出比指令小 13.4%，
> 闭环里表现为"增益莫名偏低"。测试就是为了防止这类回归。

### 控制与传感（`control.py`）

* 数字 PI：固定采样周期、零阶保持、输出限幅、**条件积分抗饱和**
  （饱和时只有朝加深饱和方向的积分被冻结，误差反号时允许回退）。
* 串级结构：位置 → 速度 → 电流。**每一级的限幅落在 PI 内部**，
  而不是算完在外面夹一下——后者会掩盖积分饱和。
* 编码器：4 倍频量化、方向反转、量纲混淆、抖动。速度只能由计数差分得到。

### 整机模型（`robot.py`）

* 母线：内阻压降、一阶热模型、温度降额；
* CAN：帧开销含 20% 位填充上界，给出负载率与排队抖动估计；
* 安全链状态机：`init → ready → running → stopping/fault/estop`，含看门狗；
* 电源预算：峰值、平均与推荐容量（含裕度）。

## 四、故障语义（重要）

故障**只作用于测量与执行通道**，物理状态永远由 `deriv` 推进：

| 故障 | 建模方式 | 期望现象 |
|---|---|---|
| `encoder_reversed` | 计数取反（位置与速度一起） | 闭环变正反馈，一使能就发散 |
| `phase_swap` | 执行器符号取反 | 电机物理反转，位置环无法收敛 |
| `units_confusion` | 角度按弧度处理 | 反馈放大约 57.3 倍 |
| `sensor_bias` | 位置加固定偏置 | 位置环稳定在偏差处 |
| `vbus_sag` | 端电压随电流下降 | 加速段饱和、失速 |
| `mechanical_jam` | 负载叠加堵转值 | 持续饱和、温升 |
| `can_dropout` | 部分周期指令保持 | 指令阶跃、跟随变差 |

这样设计的目的：让学员看到"控制变差"而不是"数据被篡改"。

数值发散（例如反馈极性接反导致的闭环正反馈）会**如实停止并报告**，
绝不会把 NaN 或 1e300 当成曲线交给前端。

## 五、已知边界（不要超出这些结论）

1. 电机是**平均值模型**：无齿槽转矩、磁路饱和、铁损、温度对电阻的影响。
2. 逆变器**不含死区与开关损耗**；过调制只做按比例回缩，不建模谐波注入。
3. 电流**没有保护模型**：超限只给告警。过流、过温、堵转保护是第 9–10 周的设计内容。
4. 热模型是**一阶集总参数**，只用于建立量级直觉，不可用于热设计。
5. 编码器模型不含安装偏心、AB 相抖动与多圈溢出。
6. CAN 抖动用排队近似，真实总线还受终端电阻、线长与拓扑影响；估算值应视为上界。

## 六、性能预算

控制周期 1 ms、子步 0.1 ms、时长 10 s 时约有 10⁵ 个子步，
纯 Python 求解约 0.5–2 s。服务用两个工作线程限流，
单次运行上限 60 s，超出如实标记失败。

如果在更慢的机器上运行，建议把 `substep` 放宽到 0.2 ms
（测试给出 0.1 ms 与 0.025 ms 的结果差小于 0.5%，0.2 ms 仍有余量），
而不是缩短 `duration`——后者会丢掉要看的现象。
